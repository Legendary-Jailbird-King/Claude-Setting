# 常见问题 FAQ

---

## 配置相关

### Q1: 配置文件应该放在哪里？

**A:** 在项目根目录创建 `.claude` 文件夹：

```
your-project/
└── .claude/
    ├── settings.json
    └── CLAUDE.md
```

---

### Q2: settings.json 和 settings.local.json 有什么区别？

**A:** 

| 文件 | 用途 | 是否提交 Git |
|------|------|-------------|
| `settings.json` | 项目共享配置 | ✅ 提交 |
| `settings.local.json` | 本地个人配置 | ❌ 不提交 |

---

### Q3: 配置不生效怎么办？

**A:** 按以下步骤检查：

1. 确认文件位置正确：`.claude/settings.json`
2. 确认 JSON 语法正确
3. 重启 Claude Code
4. 检查文件编码是否为 UTF-8

---

### Q4: 如何让所有项目使用同一套配置？

**A:** 在用户目录创建全局配置：

```bash
# Windows
C:/Users/你的用户名/.claude/settings.json

# macOS/Linux
~/.claude/settings.json
```

项目配置会覆盖全局配置。

## 权限相关

### Q5: 为什么我的操作被拒绝了？

**A:** 检查以下几点：

1. 操作是否在 `permissions.allow` 中
2. 操作是否被 `permissions.block` 禁止
3. MCP 操作是否添加了对应权限

```json
"permissions": {
  "allow": ["操作权限"],
  "block": ["禁止的操作"]
}
```

---

### Q6: 如何限制 Claude 只能修改特定目录？

**A:** 在 `permissions.allow` 中指定：

```json
"allow": [
  "Write(./src/**)",      // 只能修改 src
  "Write(./components/**)" // 只能修改 components
]
```

---

### Q7: 如何禁止危险操作？

**A:** 在 `permissions.block` 中添加：

```json
"block": [
  "Bash(rm -rf *)",         // 禁止删除
  "Bash(git push --force *)", // 禁止强制推送
  "Write(./node_modules/**)"   // 禁止修改依赖
]
```

## CLAUDE.md 相关

### Q8: CLAUDE.md 写多长合适？

**A:** 建议 300-500 字，太长 Claude 会忽略。

重点写：
- ✅ 技术栈
- ✅ 目录结构
- ✅ 编码规范
- ✅ 常用命令

不需要写：
- ❌ 太详细的历史
- ❌ 过多的示例
- ❌ 与项目无关的内容

---

### Q9: CLAUDE.md 不生效？

**A:** 检查：

1. 文件是否在 `.claude/` 目录下
2. 文件名是否正确（大写）
3. 是否重启了 Claude Code

---

## MCP 相关

### Q10: MCP 是什么？

**A:** MCP = Model Context Protocol（模型上下文协议）

简单理解：**给 Claude 安装插件**

- Filesystem MCP → 跨项目搜索
- GitHub MCP → 看 GitHub 代码
- Brave Search MCP → 搜索文档

---

### Q11: 如何配置 MCP？

**A:** 在 `settings.json` 中添加：

```json
{
  "mcpServers": {
    "名称": {
      "command": "npx",
      "args": ["包名"],
      "env": {"环境变量": "值"}
    }
  },
  "permissions": {
    "allow": ["mcp__名称__*"]
  }
}
```

---

### Q12: MCP 不工作？

**A:** 检查：

1. MCP 配置是否正确
2. 是否添加了对应权限
3. API Key 是否有效
4. 网络连接是否正常

## Skill 相关

### Q13: Skill 是什么？

**A:** Skill 是本地定义的"技能模板"，让 Claude 按特定方式工作。

- code-review → 代码审查
- explain-code → 解释代码
- write-test → 写测试

---

### Q14: 如何创建 Skill？

**A:** 在 `.claude/skills/` 目录下创建 `.md` 文件：

```markdown
---
name: 技能名
description: 描述
---

你是...（角色定义）

## 步骤
1. ...
2. ...

## 使用方式
说："..."
```

---

### Q15: Skill 不生效？

**A:** 检查：

1. 文件是否在 `.claude/skills/` 目录下
2. 文件名是否正确
3. frontmatter（---之间的内容）是否正确

## 模型相关

### Q16: 应该选择哪个模型？

**A:** 

| 模型 | 适用场景 |
|------|---------|
| `sonnet` | 日常开发，平衡性能 |
| `opus[1m]` | 复杂任务，长代码 |
| `haiku` | 简单修改，格式化 |

---

### Q17: 如何切换模型？

**A:** 修改 `settings.json`：

```json
{
  "model": "sonnet"  // 改成你想要的模型
}
```

---

## Hooks 相关

### Q18: Hooks 是什么？

**A:** Hooks 是自动化钩子，在特定事件时自动执行命令。

- pre-commit → 提交前执行
- file_change → 文件变更时执行

---

### Q19: 如何配置 Hooks？

**A:** 在 `settings.json` 中添加：

```json
{
  "hooks": {
    "pre-commit": [
      {
        "name": "代码检查",
        "command": "npm run lint",
        "run": "auto"
      }
    ]
  }
}
```

## 其他问题

### Q20: 如何备份我的配置？

**A:** 

1. **项目配置**：提交到 Git
2. **全局配置**：复制 `~/.claude/` 文件夹
3. **敏感信息**：不要提交 API Key

---

### Q21: 如何在团队中共享配置？

**A:** 

1. 将 `.claude/` 文件夹提交到 Git
2. 排除 `settings.local.json`
3. 团队成员克隆项目后自动使用相同配置

---

### Q22: 配置文件应该提交到 Git 吗？

**A:** 

| 文件 | 是否提交 |
|------|---------|
| `settings.json` | ✅ 提交 |
| `CLAUDE.md` | ✅ 提交 |
| `settings.local.json` | ❌ 不提交 |
| `settings.secrets.json` | ❌ 不提交 |

在 `.gitignore` 中添加：

```
.claude/settings.local.json
.claude/settings.secrets.json
```

---

### Q23: 如何重置配置？

**A:** 删除配置文件后重启：

```bash
# 删除项目配置
rm -rf .claude/

# 删除全局配置（谨慎）
rm -rf ~/.claude/
```
